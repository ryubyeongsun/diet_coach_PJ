# 2026.10 코드 보강·검증 기록

포트폴리오에 기재한 기존 기능과 정상 사용 흐름을 유지하는 범위의 후속 보강입니다. 프로젝트 기간의 본인 기여 또는 2026.08.15 개선으로 소급해 설명하지 않습니다.

## 유지한 정책

- API 경로·정상 응답 DTO, 30일 생성·첫 7일 우선 반환
- 남은 23일을 7/7/7/2일 구간으로 순차 처리, Core 5 / Max 10 / Queue 50
- 재료명 정규화·상품 점수·AI 후보 평가·캐시 정책
- 구매 개수 올림, 개별 예산 125%·전체 예산 115% 기준과 고비용 항목 제외
- TDEE·BMI 계산식과 경계값, 3D 자산·모델 선택 정책

## 수정한 오류·실패 경계

| 항목 | 변경 | 검증 |
| --- | --- | --- |
| 리소스 접근 | 서비스에서 인증 사용자와 사용자·플랜 소유자 비교 | 타 사용자 조회·수정·삭제 403, 본인 정상 흐름 유지 |
| 토큰 종류 | 일반 API는 Access Token만 허용 | Refresh Token으로 me 접근 실패, Access Token 성공 |
| 토큰 고유성·Rotation | jti 추가, 미폐기 토큰만 조건부 폐기, 변경 행 수 확인 | 같은 초 발급 구분, 재사용 거부, 두 동시 재발급 중 하나만 성공 |
| 비동기 제출 | 첫 저장 커밋 후 제출, 롤백 시 미제출 | 실제 Spring 트랜잭션 콜백 확인 |
| 일자 저장 | 별도 빈에서 항목과 합계를 원자적으로 저장 | 두 번째 INSERT 실패 시 첫 INSERT와 합계 변경도 롤백 |
| 큐 포화 | 오류 로그를 남기고 이미 커밋된 첫 7일 유지 | 거절 executor로 검증; 자동 복구는 미구현 |
| 템플릿 식단 | 누락 영양값에 기존 DB 기본값 0/false 적용 | NOT NULL 저장 실패 재현 후 30일 생성 테스트 통과; 칼로리 계산 유지 |
| 기존 사용자 생성 API | 로그인과 동일한 PasswordEncoder 사용 | 저장값 평문 아님, 기존 로그인 API 사용 가능 |
| 잘못된 요청 | DTO 검증·JSON·파라미터 오류를 400 처리 | 비정상 입력이 500으로 처리되지 않는지 확인 |

템플릿의 0 영양값은 실측 분석값이 아닌 기존 스키마의 기본값입니다. 이를 정밀 영양 분석 결과로 해석하지 않습니다.

## 테스트

```bash
cd backend
./mvnw test
```

- 전체 43개 통과: 단위 테스트 11개, H2 기반 안전성 통합 테스트 31개, 애플리케이션 컨텍스트 1개
- Java 17, Spring Boot 3.5.8, H2 2.3.232 MySQL 호환 모드
- 테스트마다 별도 fixture를 구성하며 실제 사용자 DB는 사용하지 않음
- MockMvc → 실제 보안 필터·Controller·Service·MyBatis·H2를 통해 검증
- 외부 AI·쇼핑 서비스는 대체 객체를 사용함. 식단 작업은 제어 가능한 Executor로 캡처해 제출 시점과 처리 순서를 검증함
- Refresh Token 동시 재발급은 실제 두 스레드와 DB 트랜잭션으로 검증함
- 구매 개수 1,200g/500g → 3개, 총액 9,000원, 예산 115% 포함·초과 제외 경계 검증

## 검증하지 않은 범위와 남은 정책

실제 MySQL·외부 AI/11번가 API·운영 부하·프로세스 강제 종료는 검증하지 않았습니다. H2가 MySQL의 모든 SQL·락 동작을 대체하지는 않습니다.

영속 큐·작업 상태 API·자동 재시도는 추가하지 않았습니다. 큐 포화나 프로세스 종료 후 미생성 일자가 남을 수 있습니다. 추천 후보 전부 탈락 시 대체 경로, 복합 상품 용량 파싱, Frontend/Backend BMI 정책 차이는 기존 결과를 바꾸지 않기 위해 별도 정책 개선 과제로 남겼습니다.
